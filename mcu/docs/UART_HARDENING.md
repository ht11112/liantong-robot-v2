# UART 收发交接加固候选（2026-11-05，离线）

本候选针对离线复现的收发交接、故障发布及 START/STOP 边界。现场首个 UART IRQ 的 FE 原因尚未确定；v9 在同一设备和接线下正常仍是重要对照。模拟注入 FE 不代表重现现场原因。本候选未刷入设备，健康静止和运动验收均未完成。

## 收发提交

WireOps 增加成对 critical_enter/critical_exit 和 rx_pending。生产板保存并恢复原 PRIMASK，在短提交区内检查实际 UART RXNE/BUSY/PE/FE/NE/ORE/RTOF，再核对 ring、半帧、2ms 静默、时钟和发送状态。硬件观察不会读取 RDR 或清除错误标志；错误仍交由 HAL IRQ 处理，并保持同 boot 的 UART 锁存。

构帧和 CRC 在锁外；最终发送提交及 grant 更新在锁内。构帧后出现的新故障使该缓冲被拒发，下一次轮询重构故障遥测。已提交的 110B 缓冲直到 TC 前保持不可变，之后发生的错误只能在后续帧报告。同步 hooks 必须三项齐全；全 NULL 只适用于无并发的可移植测试。

IRQ 屏蔽不会停止 UART，最后一次硬件观察也不能预知稍后开始的物理字节。本设计给出软件提交边界，不承诺杜绝电气碰撞。主机模型没有测出目标上临界区的最坏耗时，也没有证明一个 115200 字节时间内一定恢复 IRQ。整队列 CRC、遥测 CRC 和其他较长计算均不放入短锁。

## 故障与 START

ISR 仅锁存错误和入队字节，不调用 MQ 或 CAN 状态机。主循环在驱动调度前、调度后和 MQ tick 前观察硬件并先发布 MQ UART 故障，再触发原驱动停车流程；既有首个独立故障不会被覆盖。最终 CAN 提交还检查本轮中途新出现的 UART 故障：进入原 STOP 流程前拒绝新提交，停车流程继续原命令、超时和实测证明规则。已在 FIFO/总线上的命令无法撤回。

START 使用短事务，前后观察故障并重新决定 ACK；mq_start 也在重复 START 幂等返回前检查 critical_latched。锁内物理错误若在 START 的初次检查之后才出现，可能先产生 ARMING 内存瞬态；后置观察和最终 CAN 门负责阻止它成为后续启用，并把本轮 ACK 改为 UNHEALTHY。不能把‘同次轮询纠正’描述成绝无内存瞬态，也不能把内存 ACK 当成已出线 ACK。

BEGIN/COMMIT/RESET 等较长操作在锁外执行；其中途出现故障时，队列元数据或 epoch 可能已修改，再由后置同步锁存故障、请求停车并把 ACK 改为 UNHEALTHY。本候选不回滚这些元数据。检查点先发布已观察到的 UART 故障并保留既有首因，不提供所有物理故障的全局先后排序证明。

## STOP 与回波

TX busy 期间的 RX 继续进入 ring，不再按忙标志逐字节丢弃。解析器将 op128、102B payload 的遥测包络完整消费并丢弃，防止把自回波载荷中的 A55A/命令样式重新当作命令。普通命令上限仍为 64B，线格式、CRC、boot/epoch/grant 和 request 水位不变。

首次发布 UART 故障时不清空已排队字节或半帧，因此完整合法 STOP 可继续经过原 CRC、boot、形状和 request 防重放门。STOP 仍不要求当前 epoch、grant 或普通时隙；旧 request 拒绝，同 request 幂等，不放宽任何门。STOP ACK 只证明请求被处理，物理停车仍由原驱动回包和不同真实零速样本确认。

完整回波与完整 STOP 可以在模型中区分；丢失、损坏、截断或交叠的物理字节不一定可恢复。残缺包络可能吞入随后字节，ring 也有 128B 容量限制，不能保证碰撞中的 STOP 送达。故障自动请求停车、STOP 成功解析、STOP ACK 和实测停稳须分别报告。

## 验证和后续

本轮证据位于项目根目录 output/uart_hardening_20261105/，包含逐项合成条件、完整 110B 输出与 CRC 检查、源码身份、构建和独立审查结果。原保护阈值、驱动状态机、协议时窗、32KB 应用区及 4KB 栈预留保持。

不应直接复用旧诊断 ELF 的 RAM 地址、旧 boot、旧烧录工具 pin 或旧复位额度来操作本候选。任何现场部署、接线或验证需要单独具体方案及当次确认；修复离线验证不能代替健康静止验收，不恢复运动验收。
