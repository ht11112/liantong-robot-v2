# V11 半双工问答协议

RK 是 RS485 主站，STM32 收到请求才返回一帧。空闲、执行队列和锁存故障时都不主动上报。STM32 独立按 20 Hz 读取 CAN 轮速、累计 odom 和执行队列，RK 查询只读取当前快照。

## 帧与会话

串口为 115200、8N1、半双工，小端序。沿用 V10 的 `A5 5A` 帧头、字节布局、帧长和 CRC16 CCITT-FALSE（初值 FFFF，覆盖版本至载荷末尾）。版本字节改为 **11**，RK 工具和固件须成对使用。原 [V10 协议](PROTOCOL.md) 保留了完整偏移表，V11 对以下字段重新约定。

| 项目 | V11 |
| --- | --- |
| 请求 | QUERY、COMMIT、START、STOP、RESET 均为 36 字节，BEGIN、APPEND 为 46 字节 |
| 请求偏移 22 | 原 grant 字段保留位置，固定为 0 |
| 回复 | 110 字节，类型 128，含请求号、结果、当前队列、累计 odom 和故障 |
| 回复偏移 18/22 | 回复序号及组装回复时的 STM tick，每次成功提交一帧发送才推进序号 |
| 回复偏移 100/102 | 原授权窗口字段保留位置，均为 0 |
| 回复偏移 104 | 已接受请求水位，协议层拒绝不会推进 |

首次连上时，RK 发一条 QUERY（操作码 7），其 boot、epoch、request、保留字段及 task 全为 0。STM32 回当前非零 boot、epoch 和请求水位，ACK 请求号为 0。该发现查询不占用请求水位，也不改变队列。

正常请求使用当前 boot、epoch 和一个非零请求号。RK 从回复中的已接受请求水位继续递增，32 位回绕时跳过 0。STOP 仍要求当前 boot 和有效请求号，允许旧 epoch。STM32 在最近一次已受理请求完全相同的情况下返回原结果，重复的 START 不再次启用驱动。发现查询、协议拒绝以及带业务拒绝结果的已处理请求，通过各自的 ACK 和水位区分。

主站一次只允许一条请求在途，等待同一 boot、匹配请求号且 CRC 有效的新回复。超时后关闭该会话，不能自动续传、重发或 START。正常请求须等上一笔回复结束。固件收到新的有效 STOP 时会优先处理，可以替换还未发出的普通 ACK，原请求结果须按未知处理。每条回复等 RX 安静约 2 ms 后才发，待发超过 50 ms 即丢弃。

## 队列和停车

上传时暂停轮询，按 BEGIN、顺序 APPEND、COMMIT 逐条等待 ACK。队列 CRC32 仍覆盖拼接的 8 字节 canonical 段，最大 128 段。校验成功后进入 READY，START 是独立命令。运动开始后，MOVE/TURN、段间零速交接、限速、反馈保护和最终 STOP 均由 STM32 执行。断开 RK 不触发会话心跳停车，原有故障保护继续生效。

收到 STOP ACK 后，继续 QUERY 直到看到 `STOP_CONFIRMED` 和比 ACK 所带样本更新的、有效的双轮零速反馈。分别记录应答和实测停稳结果。任务故障和停车证明分别报告。超时、旧样本或仅有 ACK 时，停车证明仍缺失。

## 静止验证顺序

1. 核对当次设备身份和串口所有者，确认小车停稳、驱动供电稳定且 CAN 已连接，再使用同版本的 RK 和 STM32。先核对 36 字节 QUERY 和对应 ACK、boot/epoch 以及新鲜 CAN 源样本。
2. 上传一条测试队列，核对 46 字节 BEGIN/APPEND、36 字节 COMMIT、每条 ACK、队列 CRC 和 READY。静止阶段到此为止。
3. 单独运行连续 QUERY 基准，记录发送与匹配回复的频率、超时、CRC、RK 往返时延及 STM32 的 UART 锁存与错误码 7。RK 目标每 20 ms 开始一次，前一笔未结束就等待，错过节拍不补发。CAN 样本间隔约 50 ms，因此相邻回复可以带同一源样本。基准的 success 表示查询事务完成，50 Hz 要结合实测速率和最大间隔判定。
4. 动作验证另行开始。分别检查 START 后独立完成 MOVE/TURN、断开 RK 后继续执行、显式 STOP 的 ACK 和实测停稳。

36 字节查询加 110 字节回复在 115200 8N1 的线上时间约 12.67 ms，再加 2 ms 转向静默，距 20 ms 目标还剩约 5.33 ms，需由 STM32 处理和 RK USB/调度共同使用。离线测试可验证协议与单请求调度。能否稳定达到 50 Hz、UART 错误 7 是否复现，需要各自的现场实测记录。
