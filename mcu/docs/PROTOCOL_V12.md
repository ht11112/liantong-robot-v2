# V12 半双工问答协议与任务续约

RK 是 RS485 主站，STM32 收到请求才返回一帧。空闲、执行队列和锁存故障时都不主动上报。STM32 独立按 20 Hz 读取 CAN 轮速、累计 odom 和执行队列，RK 查询只读取当前快照。

## 帧与会话

串口为 115200、8N1、半双工，小端序。沿用 `A5 5A` 帧头、帧长和 CRC16 CCITT-FALSE（初值 FFFF，覆盖版本至载荷末尾）。版本字节为 **12**，RK 工具和固件须成对使用。STM32 消费 V10/V11 旧帧但不执行，V12 主站只接受 V12 回复。原 [V10 协议](PROTOCOL.md) 保留了完整偏移表，V12 对以下字段重新约定。

| 项目 | V12 |
| --- | --- |
| 请求 | QUERY、COMMIT、START、STOP、RESET、RENEW 均为 36 字节，BEGIN、APPEND 为 46 字节 |
| 请求偏移 22 | 原 grant 字段保留位置，固定为 0 |
| BEGIN 偏移 40 | 32 位租约长度，固定为 30000 ms |
| 回复 | 110 字节，类型 128，含请求号、结果、当前队列、累计 odom 和故障 |
| 回复偏移 18/22 | 回复序号及组装回复时的 STM tick，每次成功提交一帧发送才推进序号 |
| 回复偏移 100 | 32 位剩余租约毫秒数，按组装回复时刻计算。未执行或已过期时为 0 |
| 回复偏移 104 | 已接受请求水位，协议层拒绝不会推进 |

首次连上时，RK 发一条 QUERY（操作码 7），其 boot、epoch、request、保留字段及 task 全为 0。STM32 回当前非零 boot、epoch 和请求水位，ACK 请求号为 0。该发现查询不占用请求水位，也不改变队列。

正常请求使用当前 boot、epoch 和一个非零请求号。RK 从回复中的已接受请求水位继续递增，32 位回绕时跳过 0。STOP 仍要求当前 boot 和有效请求号，允许旧 epoch。完全相同的最近请求复用原结果，重复 START 或 RENEW 不会重置计时。发现查询、协议拒绝以及带业务拒绝结果的已处理请求，通过各自的 ACK 和水位区分。

主站一次只允许一条请求在途。普通 odom QUERY 在截止前未收到匹配回复时，丢弃本轮样本，下一轮使用新的请求号。网页按最后一个有效样本的年龄判断反馈时效。发现、上传、START、STOP 和 RENEW 都需要匹配回复，命令结果不确定时结束会话。固件收到新的有效 STOP 时会优先处理，可以替换还未发出的普通 ACK。每条回复等 RX 安静约 2 ms 后才发，待发超过 50 ms 即丢弃。

## 队列和停车

上传时暂停轮询，按 BEGIN、顺序 APPEND、COMMIT 逐条等待 ACK。队列 CRC32 仍覆盖拼接的 8 字节 canonical 段，最大 128 段。校验成功后进入 READY，START 是独立命令。MOVE/TURN、段间零速交接、反馈保护和最终 STOP 由 STM32 执行。

离线对接候选增加两种单段动作：kind 3（DOCK_MOVE）距离在 [-1.0, -0.005) 米，kind 4（DOCK_TURN）角度绝对值在 (1°, 5°]。不接受小于或等于停止容差的动作，以免未经运动即完成。含任一对接动作的队列必须恰好一段；APPEND 帧布局和 CRC 不变。两种动作固定 1 RPM，倒车目标为左轮负、右轮正；按动作方向计算实测进度，分别在剩余 5 mm 或 1° 时走原 STOP 与实测停车路径。普通动作容差和行为不变。旧固件会以 INVALID 拒绝这些段，主站必须确认每条 APPEND 和 COMMIT ACK 成功才可 START；不可凭 V12 版本或未知能力位推断支持。此候选仅离线验证，阈值不是现场精度证明。

START 成功后，STM32 从当时开始计 30 秒。RK 导航进程只给自己成功启动的任务续约，收到新鲜反馈且估算剩余约 5 秒时，发送 RENEW（操作码 8），在偏移 26 填该任务 ID。STM32 仅接受身份匹配、仍处于使能、行走、转向或段间交接且租约未到期的健康任务，从收件时刻重计 30 秒。续约不要求已行驶指定距离。

过期走现有停车流程，任务错误码为 3。STOP、故障、完成、过期或会话变化后，续约无法让任务重启。RK 失联后，STM32 至多执行到最近一次租约到期。20 分钟固定总时限取消，路线容量仍为 128 段。网页控制端断开时，仍在正常运行的 RK 会继续给自己启动的任务续约。

收到 STOP ACK 后，继续 QUERY 直到看到 `STOP_CONFIRMED` 和比 ACK 更新的有效双轮零速反馈。每次查询必须能等满应答窗口，停稳确认到期后继续更新底盘状态。任务故障、命令应答和实测停稳分别报告。

## 静止验证顺序

1. 核对当次设备身份和串口所有者，确认小车停稳、驱动供电稳定且 CAN 已连接，再使用同版本的 RK 和 STM32。先核对 36 字节 QUERY 和对应 ACK、boot/epoch 以及新鲜 CAN 源样本。
2. 上传一条测试队列，核对 46 字节 BEGIN/APPEND、36 字节 COMMIT、每条 ACK、队列 CRC 和 READY。静止阶段到此为止。
3. 单独运行连续 QUERY 基准，记录发送与匹配回复的频率、超时、CRC、RK 往返时延及 STM32 的 UART 锁存与错误码 7。RK 目标每 20 ms 开始一次，前一笔未结束就等待，错过节拍不补发。CAN 样本间隔约 50 ms，因此相邻回复可以带同一源样本。基准的 success 表示查询事务完成，50 Hz 要结合实测速率和最大间隔判定。
4. 动作验证另行开始。先验证正常 STOP，再验证持续续约、撤去 RK 后按最后一次租约到期停车，以及到期或停车后拒绝迟到的 RENEW。分别记录 STOP ACK 和实测停稳。

36 字节查询加 110 字节回复在 115200 8N1 的线上时间约 12.67 ms，再加 2 ms 转向静默，距 20 ms 目标还剩约 5.33 ms，需由 STM32 处理和 RK USB/调度共同使用。离线测试可验证协议与单请求调度。能否稳定达到 50 Hz、UART 错误 7 是否复现，需要各自的现场实测记录。

连续倒车候选（2026-11-12）将kind3上限从5厘米扩到1米，kind4仍为原短转。MCU租约仍为30秒，不接受125秒租约；RK连续倒车按原RENEW延长租约，并从实际START发送时刻执行独立的最多约125秒停止预算。旧短步与搜索/初转不续租。新候选未烧录，历史5厘米固件与失败/回读记录保留。
