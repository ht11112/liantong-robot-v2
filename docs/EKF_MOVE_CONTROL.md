# EKF 直行闭环纠偏

第十分支从第九分支 `8e92c4e` 开发。RK 根据融合位姿计算规划直线的航向误差和横向偏差，按约 10 Hz 下发差速修正，MCU V13 在引导 MOVE 内执行。分支交付状态为离线验证。

## 位姿与规划线

启用 `--ekf-move-correction` 时，人工置零或单次 AMCL 对齐要求轮式反馈和 EKF 都新鲜且满足停稳条件。EKF 线速度与角速度门槛由现有双轮 0.2 RPM 零速容差及轮径、轮距换算。定位时建立固定的地图到 EKF 局部坐标变换。

地图车标、轨迹和纠偏使用对齐后的 EKF 位置与朝向。每段 MOVE 的参考线从上传队列的规划起点及此前 TURN/MOVE 累计得到，保留转向结束时的实际角度误差。雷达仍先与真实轮式反馈配对，再按扫描时间在融合位姿历史的两侧样本间插值投影。跨估计缺口和没有时间包围的扫描等待后续有效帧。

MCU 重启、里程计代次变化或反馈历史失效后，需要重新定位。EKF 状态过期时，RK 请求停车。MCU 另按 STEER 所用轮式测量时刻约束修正期限。

## 控制方式

横向偏差为车体位置到规划直线的有符号距离。控制器根据偏差给出朝向原线的小角度，再结合航向误差和融合角速度阻尼计算轮间差速。正差速表示左转，通过降低左轮给定实现。

| 默认试验参数 | 数值 |
| --- | --- |
| 修正目标频率 | 10 Hz |
| 横向回归前视距离 | 0.5 m |
| 最大回归方向角 | 8° |
| 航向比例增益 | 0.8 /s |
| 偏航角速度阻尼 | 0.3 |
| 轮间平均差速上限 | 1 RPM |
| 航向与横向联合死区 | 0.2° 且 0.5 cm |
| MCU 接受的差速范围 | ±2 RPM |
| 修正有效期限 | 所用 MCU 测量时刻加 500 ms |

这些数值用于首轮离线候选，控制器参数在 `app/v13_move_control.py`。轮径 0.20 m、轮距 0.30 m 延续项目估计值，需要实测标定。

当前驱动目标以整数 RPM 下发。MCU 每个实际接受的 100 毫秒目标槽累计 milliRPM 的小数余量。例如 0.25 RPM 平均修正由若干整数目标槽组成。等待 CAN 应用时，目标槽顺延。机械平稳性和实际轮速响应须由实车验证。

## 执行与路线校验

显式启用时，RK 将导航 MOVE 编码为 `guided=true` 的类型 3，并重新计算队列 CRC。上传到 READY 后仍需用户点开始。每段引导 MOVE 等待首条有效修正，之后 MCU 同时执行距离判定、差速给定及既有停车流程。主站 STEER 应答进入共享反馈缓存，STOP 使用同一个串口 owner 的优先取消通道。

纠偏中的剩余扫掠按固定规划线和最多 0.5 m 的局部接回段检查，接回处使用现有转向圆盘和连接扫掠。偏离规划线时，该几何会保守拒绝狭窄处的修正。15 厘米净距仍按实际矩形和转向外接圆检查。段完成沿用 MCU 实测中心轮程，末段 MOVE 的结束容差为 10 厘米。

## 离线验证与后续使用

MCU 构建入口为 `python -B mcu/build.py --host-tests --firmware --move-cruise-rpm 5 --move-near-rpm 3 --turn-rpm 3 --name 新的候选名称`。链接应用区为 32 KiB，构建收据给出 BIN/ELF SHA、Flash、RAM 和栈余量。

RK 沿用保存地图导航入口，在对应启动参数中加入 `--ekf-imu-topic /imu/jy901/data_raw --ekf-move-correction`。MCU 与主站均使用协议版本 13。构建包清单的 `wire_version` 为 13，历史构建脚本和归档文件名沿用仓库原名称。

测试使用生产 C 状态机、模拟驱动、真实 Python 共享缓存及生产控制器，覆盖正负修正、低速限幅、分数平均、CAN 应用延迟、时间回绕、段切换、修正过期、STOP、坐标旋转、角度跨界、两侧偏差回归及雷达融合投影。动态角度、路线精度和机械平稳性属于后续现场验收。
