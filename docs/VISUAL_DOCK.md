# 一次识别、一次规划、连续倒车回桩候选

2026-11-12 在第九 `fd80726` 基线上更新。当前实机仍为此前5厘米短步固件和曝光修正RK包；本文新流程只有源码与离线候选，尚未烧录、部署或实车验证。历史3厘米动作成功到段但强制复拍失败的记录原样保留，不把它改称整次任务通过。

## 当前流程

网页保存绑定当前 `map_id` 的桩X/Y和朝向（朝空地的方向），接口为 `POST /api/dock/config`。默认桩(-0.5,0)、朝向+X，桩前0.70米等待点为(0.2,0)，轮轴参考终点为(-0.25,0)。`--dock-config` 指定JSON保存位置，默认 `~/.local/state/liantong-robot/dock-config.json`，重启保留；地图改变时使用该地图默认值。地图叠加桩、等待点和轮轴目标，不自动置零或改变用户手动定位。

点击「开始回桩」后，先复用普通地图导航驶近等待点（含原避障和续租）；到点经STOP及实测停车证明后，从唯一相机owner重新打开相机、预热并取新照片。没有目标时保留完整3秒曝光等待；到期时若本轮仍有新鲜有效图像但无ID1，返回该图供判断，而不是误报无图。有新图但无ID1／错ID可搜索下一方位；无新图、采集失败或ID1的视觉参数无效则停车结束。重开不等于精确获知曝光时刻，也不能证明相机内部无缓存。

搜索用普通kind2 TURN单段，不借用必须以MOVE结尾的地图队列。第一张图即在原方位拍摄，随后名义每30°停稳拍照、最多搜索一圈；每次给定按同一搜索起点的连续累计**实测**轮式转角补足下一方位，处理±180°回绕。原普通TURN有3°结束容差，网页报告实际累计角，不能把12条30°命令称为精确实转360°。

首张有效ID1照片立即结束搜索，直接作为唯一近距离测量。tag36h11 ID1黑色边长0.08米，不含纸白边；MF200仍640×480及原内参。相机居中朝后、轮轴后移量采用约0.175米、离地0.14米，安装角沿当前配置，均不宣称已精密标定。PnP变换得到车体系标签平面位置p和朝空地的水平单位法线n，轮轴目标 `q=p+0.25*n`。只接受当前后方且倒车长度大于5毫米、不超过1米的目标。计算一次初转 `atan2(-q.y,-q.x)` 和倒车长度 `|q|`；初转大于普通TURN结束容差时，先转向并实测停稳，然后一次连续倒退；否则直接倒退。初转不使用EKF或V13纠偏。

照片到START沿用2厘米／2°起点、MCU会话、实测停车和取消围栏。取消“五条原始轮计数不变”及原始计数完全相等门槛。初转停稳后只建立新的上传起点，不重新拍照或重算终点。倒车中不分段、不拍照、不重新规划；照片过期、标签消失或网页延迟不作为运动门槛。末端不复拍、不调整朝向、不用此前20±2厘米／横偏2厘米／朝向3°判断失败。完成显示「倒车计划执行完成，已停稳」，不代表充电或地图/尺量精度通过。

轮轴距桩平面0.25米对应正对镜头距平面约0.075米，8厘米标签可能无法完整入画，因此不要求终点识别，也不承诺最终车头精确平行桩法线。近场目标依据唯一照片，地图桩位只用于驶近；地图读数与现场尺量分开记录。

## MCU、租约及停车

连续候选只将kind3 DOCK_MOVE单段倒车上限5厘米扩大到1米，负距离、1RPM及5毫米结束容差不变。普通MOVE/TURN、kind4短转、33V上限、普通5/3/3RPM和实测停车参数保持；V12 wire不变，无V13 STEER。旧固件可能拒绝长段APPEND，必须全部确认READY后才START。

连续倒车和驶近可按原身份及新鲜反馈条件续租，仍是MCU30秒租约、剩余约5秒时续租；旧短步测试、搜索和初转不续租。以1RPM名义 `π×0.20/60 m/s` 计算，在实际START发送时刻建立RK总预算 `max(30, ceil(1.25×距离/名义速度+5))` 秒，1米约125秒。到期发原STOP并撤销续租；这是RK预算，MCU仍仅保证最后一次续约后30秒租约，不能称为MCU独立125秒硬截止。人工STOP、底盘故障、真实反馈失效保留原停车机制，停止后不自动恢复。

`/api/dock/step`及显式 `--dock-single-step-test` 保留，用2～5厘米倒车或kind4小角度转向验证；一次动作并实测停稳后结束，不再强制复拍，也不会自动切入连续流程。网页后视预览仅作参考，与停稳照片独立。

## 验证和后续现场阶段

离线验证真实PnP/几何、搜索/取消/超时、连续倒车续租及预算、旧短步不续租、真实C的1米边界/1RPM/5毫米/STOP和普通导航。候选固件严格32KiB；构建、来源及哈希见本轮收据。源码与候选打包不表示已经烧录或运行。

现场阶段须重新核当次设备和条件。先静态识别，再短距，随后连续倒车、完整回桩；先正对，再左右偏移并尺量终点。雷达不覆盖后方近场，首轮须当次后方清空和人工看护。本轮不自动开始这些阶段。

## 历史短步方案与静态记录（已由上述流程替代）

本候选沿第九分支开发，使用 tag36h11 和独立于地图定位的短步倒车。停靠局部坐标中标签中心为 (-0.4, 0) m，目标轮轴为 (0, 0)，车头朝 +X；相机居中、位于轮轴后 0.20 m、朝后。完成条件是停稳后的新鲜观测满足相机到标签 0.20±0.02 m、轮轴横向偏差不超过 0.02 m、朝向误差不超过 3°。状态称为“视觉对准完成”，不表示充电。

用户更正黑色标记方框边长为 8 cm，相机中心离地为 14 cm；相机水平且居中正对车尾。静态预览已识别 tag36h11 ID 1；尺寸、安装角度和测距仍需现场核验。纸张白边不计入标记边长。

RK 相机使用独立线程请求 MJPEG 640×480，直接加载同包内已复核的 `mf200_640x480.yaml`，需要 Python 的 NumPy、PyYAML 与支持 `DICT_APRILTAG_36h11` 的 OpenCV aruco。本轮只读预览已核对设备、依赖及 MJPEG 640×480；标定几何仍需现场验收。PC 通过现有 SSH 连接的独立通道取 JPEG；预览可能延迟，网页另显示本步的编号参考照片，照片不是实时画面。

每次实测停稳后，先等待同一 MCU 会话中连续五条不同的新鲜轮式采样，其左右原始计数完全相同，再由相机线程关闭并重开设备，从本轮采集生成照片和观测；稳定等待和拍照共用 3 秒预算。首次读取仅用于预热，对没有识别出标签的画面继续读取，识别到标签时以该帧作为本轮照片。此前实机出现过曝导致未识别，继续读取用于等待曝光稳定，不能证明相机内部缓存已清除。识别到错误 ID 或拍不到有效目标则结束任务并保持停车。每张照片绑定本步的 MCU 会话和轮式起点，上传和启动前重新确认未取消、反馈有效且起点未变；照片不得跨动作复用。重新打开用于清除本进程及驱动队列，不能据此保证相机内部没有缓存或得知曝光时刻，须在现场改变标签位置后验证实际照片。

RK 启动时显式指定 `--dock-camera` 才启用只读画面。目标 ID、尺量边长（米）及相机高度、yaw/pitch/roll 安装角须分别使用 `--dock-tag-id`、`--dock-tag-size-m`、`--dock-camera-height-m` 和 `--dock-camera-yaw-deg`、`--dock-camera-pitch-deg`、`--dock-camera-roll-deg` 指定。只读预览不需要打开 `--dock-visual-verified`。在确认成像模式、标定和 50/30/20 cm 及左右偏移的静态测距、方向和完整入画通过之前，不使用该开关。开启它也不能代替现场确认和逐步动作验收。

对接须配套本候选 MCU：V12 单段 kind 3 倒车及 kind 4 转向，不兼容旧固件的动作能力；旧固件拒绝上传时不会发送 START。固定 1 RPM，每步倒车不超过 5 cm、转向不超过 5°；结束容差分别为 5 mm、1°。每个对接单步只使用 MCU 原有的 30 秒租约，不自动续租；普通导航仍按原规则续租。已接受的短步执行期间不依赖参考照片保持新鲜或标签持续可见，结束并确认停稳后重新拍照；如新照片无有效目标，任务结束且不自动恢复。人工停车、底盘故障或反馈失效仍触发原停车机制。普通 MOVE/TURN 和既有 5/3/3 RPM 保留；候选固件沿用实机 33V 上限和停车证明参数。MCU 到段不等于视觉对准或尺量精度通过。

首轮现场单步接口默认关闭。经过静态验证并在当次场地确认后，可在 RK 启动时额外指定 `--dock-single-step-test`，使用既有 PC 网关同源令牌向 `/api/dock/step` 提交 JSON：`{"kind":"move","value":-0.03}` 表示倒车 3 cm；`{"kind":"turn","value":0.0523598776}` 表示逆时针约 3°。倒车范围为 2～5 cm，转向绝对值大于 1° 且不超过 5°。单次完成并实测停稳后结束，不自动进入闭环；接口仍要求视觉有效、底盘停稳，并与普通导航互斥。当前网页没有为此接口提供单步按钮。

本轮只部署独立的只读相机预览，导航候选与固件候选均未部署或烧录，未执行实车动作。后方近场不受现有雷达保护。现场工作需重新核对实际设备、场地与停车状态，清空后方并人工看护；依次做静态图像检查、2～5 cm 倒车和左右小角度单步，再接视觉闭环。正对、左右偏移均需重复并尺量终点，另覆盖遮挡、断流、错误 ID 和人工停车。

2026-11-11 只读预览中，用户报告约 50、30、20 cm 时，视觉距离分别约 50.3、29.9、20.4 cm；用户报告的距离为大致值，不能据此计算精确误差或判定通过。20 cm 处用户报告一次横向移动约 5 cm，偏差读数从约 +1.0 cm 变为 −4.4 cm。随后标签移出画面右缘，识别状态显示丢失。这些观察均在独立预览、`verified=False` 下完成，安装角暂按零计算；图片来源与样本保存在项目工作区 `output/dock_static_20261111`。出现标签旋转 90° 时横向公式错误，已修复并用四个图案旋转方向合成回归；仍需相反偏移、精确尺量、缓冲延迟及现场动作验收。
