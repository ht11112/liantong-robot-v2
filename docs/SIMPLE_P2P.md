# 简版点到点控制

本分支提供RK本地单目标程序，以及PC本地网页操作入口。控制算法不使用地图、AMCL、DWA或Pure Pursuit，也不加载手推地图；网页可只读展示保存地图，并用独立局部坐标图设置目标：

| 状态 | 动作 | 结束条件 |
| --- | --- | --- |
| 对准 | 线速度0，原地转向目标；接近角度时减速 | odom航向误差≤3° |
| 直行 | 两个物理车轮等速正向，角速度命令0；接近目标减速 | 距离≤10cm |
| 重对准 | 航向误差>8°时先零给定、实测停稳，再转向 | 重新对准后直行 |
| 正常结束 | 零目标真实应用、五个新零速且编码器稳定；再STOP、健康失能及五个postSTATUS新零 | 最终位置及停车证据均通过才成功 |

有效量程内的几何碰撞、反馈/扫描超时、里程计缺段、取消或单任务超时均终止并停车；当前1m下限对车体附近的测障限制见参数说明。不绕行、不倒车、不调整终点朝向，失败不自动重新ARM。页面关闭和PC断网不改变RK本地任务；没有网页在线心跳要求。

指令接收与实际应用分别核对：STATUS和SETPOINT回包中的`last_applied_seq/target_pack`都参与应用验证，单独收到ACK不代表已应用。300ms内确实没有应用进展仍停车。停车保留原0.2RPM标准，在原2秒窗口内等待五个连续不同的新零速样本；期间非零会清零计数重新等待，来源或状态错误仍拒绝。停车确认和最终位置证明分开，停车积分断段不会补位移或冒作已验证位置。

执行任务的最终STOP链若未取得匹配ACK，只在原事务结束后由同一owner/串口FD额外发送一次新序号STOP，仍须健康失能STATUS和五个严格postSTATUS新零源。原即时STOP不等待重试；有ACK但后续状态或五零失败时不补发，补发也不循环、不ARM、不重跑目标。`final_stop_recovery`独立记录补充停车证明，原`first_failure`和`final_stop_chain`不改。补充停车成功时网页可显示“补充停车已实测确认”，但任务和位置仍失败、原点失效。

几何拒绝扫描时，`first_scan_rejection`保留首个拒绝的阶段、原header/来源时间、当前车体/雷达几何及最多8个命中点、首点附近最多5束。距离、角度和车体坐标保留测量值，正无穷无回波用显式null和分类表示；不把近点自动判为自身或噪声。证据在扫描回调预计算，控制线程只复制有界快照，完整JSON仍在串口关闭后保存。新任务和置零清除旧诊断；历史任务未保存的原扫描不能事后补造。

正常到点时先用零速度给定停稳，继续按真实反馈逐样积分。在零目标已真实应用后，五个不同且全源严格晚于该应用观测的样本需同时满足原0.2RPM门和编码器稳定，才封存位姿及两原始编码器。该阶段最多2秒，仍受原任务时限、反馈/扫描、应用和租约检查约束；取消、故障直接STOP，不等待封存。

现有可追溯固件在STOP清理时暂停完整轮速采样，因此正常封存后不跨这段空窗积分、插值或重锚。STOP后的所有可用反馈编码器须与封存值相同，且原健康失能STATUS和五个postSTATUS新零源均通过，才能以“先实测停稳、再核编码器保持不变”证明封存位置保持。任一编码器变化或封存前真实缺段都拒绝位置验证；后来的零速不能挽救。封存位姿保留原测量/来源时间，停车确认时间另记，这不是恢复了STOP中的连续里程计。最终距离仍用已证明保持的停车位姿核对10cm容差。

## 数据与控制时序

单一线程拥有唯一串口FD，最多一笔请求在途。协议返回的真实FEEDBACK逐条校验、去重并立刻积分，控制器每50ms独立读取最新累计位姿；串口回包等待不会阻塞控制tick。只有尚未发送的控制意图可由更新意图替换，原始反馈不采用“只保留最新一条”。在途SETPOINT绑定发送时的命令快照，后来的意图不能改写它。MCU未返回的样本无法补回，仍由真实序号和速度tick检查发现缺段。

轮速查询计划周期40ms，STATUS为200ms，同目标保活100ms，变化目标最快50ms一次。它们按到期先后共享串口，受真实回包延迟影响，计划周期不表示硬实时保证。超期的控制tick跳过，不逐条追赶旧控制意图；完整结果保存实际查询间隔和每次控制使用的位姿来源。MCU500ms租约、真实应用300ms和原反馈750ms均保持。

最多256个已积分位姿构成短历史。`latest`用原CAN来源下界检查750ms新鲜度；插值轴使用首个真实源锚点加MCU速度tick增量，避免保守CAN年龄下界波动造成时间回退。两条时间轴独立记录，这不是MCU与ROS的精确时钟同步。`sample_at`仅在同一连续段的实测区间内对x/y线性插值，yaw沿最短角差插值；区间之外直接拒绝，不外推。

控制当前只取`latest`，历史查询用于后续有共同时间基准的数据对齐。ARM零目标交接仍须真实静止与编码器不变，之后从新READY反馈开启历史段。运动中真实MCU样本跳号或速度tick跨度超过250ms仍锁存缺段并停车，不靠插值、重新锚定或扩大750ms门限继续走。转向/直行切换仍经过零命令及五个不同的新实测零源。

网页的原始反馈与累计位姿分别保留来源时间，单独的新原始包不刷新旧位姿年龄。实时状态由后台writer保存；任务结果在串口关闭后先写临时文件、fsync再原子替换，降低断电时完整结果丢失的风险。结果损坏会报告证据错误，不算成功，也不阻塞活动任务的取消；任务归属元数据损坏仍阻止新owner。

## 坐标与置零

用户把车推回地面标记并停稳后，`--reset-odom`以首个健康静止反馈把**本次进程**的位置和车头设成`(0,0,0)`。这是软件参考系，不重置STM32编码器。`x`沿起始车头向前，`y`向左，角度逆时针为正。目标单位为米。

直接CLI的每次独立启动均创建新零点，必须使用新的输出目录；不跨未记录的手推、重启或程序退出恢复旧位姿。`origin.json`是本次零点证据，不是常驻odom服务。只建立零点的程序结束后，若再次移动，下一次执行应在选定起点重新停稳置零。不能拿上轮目标或手推地图的map坐标直接当成本轮odom目标。

网页的“设置原点”同样只建立软件局部参考，不清零MCU编码器。预览不启动运动；执行时会核对原点参考所对应的编码器。空闲时手推、重启或发现编码器改变后必须停稳重设原点，不能继续沿用页面中的旧坐标。网页状态保存用于显示与核对，不等于持续运行的里程计。

例如，起始车头为+X、目标`(1,1)`，先左转约45°，再直行约1.41米，实际终止由测得的odom和10厘米容差决定。车体尺寸和雷达平移使用操作者提供的现场测量值；轮径、轮距及雷达朝向等仍未完成系统标定，所以该例不是地面精度保证。

## 参数

配置为[`config/simple-p2p.json`](../config/simple-p2p.json)。按用户当前要求，额外停障净距`stop_clearance_m=0`，取消原先在车体边界外增加的20cm距离；导航雷达最小有效距离`min_usable_range_m=1.0`。其余参数沿用：前进上限0.03m/s、转向上限6.9°/s、到点误差0.10m、单次200s、RK原轮速来源750ms失效。MCU原CAN250ms、500ms目标租约、±5整数RPM和15RPM异常门限保持。

有效距离下限只用于RK点到点导航的读取端，不改变雷达硬件规格、ROS原始发布或已保存地图。实际下限取原消息`range_min`与配置值的较大者，上限仍按原消息（目前50m）。原本在消息量程内、但低于新下限的有限回波保留原值与排除分类，计入过滤数，不参与几何；NaN、负无穷、原消息量程违规、时间/布局错误仍拒绝。至少10个有效量程内有限前束的原要求不放宽，只有近点或无回波不能冒作有效远场扫描。正无穷只表示无回波，不证明净空。

当前车体矩形距雷达最远角约0.365m、转向扫掠圆最远点约0.396m，均小于1m。因此此配置使现有矩形/转扫碰撞门不再覆盖近场；几何算法仍计算有效量程内回波，但不能宣称车体附近有障碍必停车。`scan_policy`记录原始/配置/有效下限、过滤数和近场覆盖状态，网页显示“1m内不提供测障”。该下限不等于1m停车距离，原反馈/扫描来源、应用、租约及取消停车逻辑不变。

3°对准、8°重对准、0.30m/20°开始减速是本版可配置工程值。名义轮径0.20m、轮距0.30m保持。2026-11-04操作者提供现场尺寸：以驱动轮轴线中点为基准，车体前后各0.175m、总宽0.40m（半宽0.20m），雷达中心前移0.13m、左右偏移0。配置采用上述尺寸，雷达yaw仍为0、未另做朝向标定。原地转向扫掠半径随真实尺寸计算为约0.26575m。障碍检查仍从车体坐标边界和转向扫掠范围计算，额外净距为0；不把近点自动屏蔽为自身回波。

硬件给定只能整数RPM。程序向下量化并重新核算速度上限：名义几何下直行最高2RPM（约0.02094m/s），近目标1RPM；原地转向1RPM（约4°/s），不会把2RPM约8°/s当作≤6.9°/s。命令零不当作实测停稳。

只有前180°雷达，无法证明整个原地转向扫掠区域已清空。需要转向时，操作者须核对车体四周和后方；`--turn-area-clear`记录这次现场检查，雷达仍检查它实际覆盖的前方障碍。缺该标记时需要转向的任务拒绝运动，不用前方净空冒充全周净空。

```text
python -B -m unittest discover -s app -p "test_*.py"
python -B scripts/verify_source.py --verify-manual-import --verify-r5-baseline
python -B scripts/build_simple_p2p_package.py --name simple-p2p-build-1
python -B -m unittest discover -s dist/simple-p2p-build-1/package -p "test_simple*.py"
python -B -m unittest discover -s dist/simple-p2p-build-1/package -p "test_local_p2p_remote.py"
```

独立包只含简版源码、RK `local_p2p_remote.py`、必要通信依赖、对应测试和配置，不包含地图、凭据、固件、PC网页服务或旧导航。manifest记录两个运行入口及文件SHA，构建结果仍明确 `deployed=false` / `launched=false`。输出目录已存在时拒绝覆盖。打包本身不部署或启动。

## 本地网页

按[USAGE中的本地网页命令](USAGE.md#本地局部坐标网页)启动PC `scripts/run_local_p2p.py`，浏览器访问 `http://127.0.0.1:8766/`。设原点和预览均不发车；每次执行必须显式选择目标并确认当次现场。地图仅只读参考，局部坐标、原点和目标单独显示，不假定存在地图定位。

PC通过RK的 `probe/start/poll/cancel` 任务入口工作，不直接访问底盘串口。RK进程独占串口并在本机完成任务；页面关闭或PC断开后，原200秒及传感器/停车边界继续有效。任务输出保留在本次新目录，取消只作用于本次任务。原手推只读网页源文件和它的9源包不变。

## RK使用

使用RK现有系统Python3.8、pyserial；运动时另需现有ROS Noetic的rospy和sensor_msgs。不要用PC requirements覆盖RK的系统ROS依赖。新包放入独立目录，以下示例均在其`package`目录执行；`BOOT_UUID`须换成当前`/proc/sys/kernel/random/boot_id`，输出目录须是新目录。

只建立零点（不订阅ROS、不STOP、不ARM、不下轮速）：

```text
python3 -s -B simple_p2p_runtime.py --expected-boot-id BOOT_UUID --output-dir /home/cat/simple-origin-001 --reset-odom
```

显式执行单次相对目标的命令如下。只有在当次现场允许运动、车上无人且可人工停车，已检查整个转向区域时才运行：

```text
python3 -s -B simple_p2p_runtime.py --expected-boot-id BOOT_UUID --output-dir /home/cat/simple-goal-001 --reset-odom --goal-x 1 --goal-y 1 --turn-area-clear --execute
```

RKROS环境应已设置`PYTHONPATH=/opt/ros/noetic/lib/python3/dist-packages`、`ROS_MASTER_URI`等当前系统参数；代码不修改系统服务。扫描默认`/lidar1/laser_fan`，原header时间计龄，重复帧/反馈不续鲜。MCU定位用本机USB身份识别，不固定ttyUSB编号；同一个进程独占串口。

取消可给该进程SIGINT/SIGTERM，或在当次输出目录创建`cancel.request`。取消只终止任务并确认停车；没有任务时不要给其他进程发信号。程序结束后保存`result.json`和`origin.json`，原始收发在有界内存保存并在串口关闭后落盘；失败首因和最终停车结果分别记录。不要把普通进程退出或STOP回执单独当作停车确认。

当前分支的自动化测试只验证软件行为。实车原地转向、到点误差与停障仍需当次任务验收；这次提交不会自动运行示例目标，也不更改旧手推网页或开机服务。
